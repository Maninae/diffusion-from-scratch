The U-Net has been diffusion's workhorse, but it doesn't scale cleanly — you can't just make it bigger and reliably get better results. Transformers can. We'll replace the U-Net with a simpler architecture: patchify the image into tokens, process them with standard transformer blocks conditioned via adaLN-Zero, and unpatchify back. The result scales predictably with compute, and it's what powers Stable Diffusion 3 and DALL-E 3.

The Trend: Transformers for Everything

We've spent the last several lectures building and improving U-Nets for diffusion. The U-Net has been the workhorse architecture since the original DDPM paper in 2020 — and it works well.

But let's be honest about what it asks of us: an encoder-decoder structure, skip connections at every resolution, attention blocks injected at specific layers, carefully tuned channel multipliers. It's a lot of bespoke engineering.

Meanwhile, a different story has been unfolding across machine learning. Transformers have conquered NLP (2017), vision classification with ViT (2020), protein structure prediction, code generation, and more.

The recipe is always the same: take a simple, repeated building block (self-attention + feedforward), stack it deep, and throw compute at it. The architecture itself barely changes — you just make it bigger.

This is exactly the property that makes transformers so appealing for scaling. They follow predictable scaling laws: double the compute, get a measurable improvement.

U-Nets don't have this property. Scaling a U-Net means deciding where to add channels, which resolutions get attention, how deep each stage should be — it's an architecture search problem, not a compute scaling problem.

So the question becomes natural: can we replace the U-Net with a transformer and get the same (or better) results, while inheriting the transformer's scaling properties?

The DiT Architecture

The answer is DiT (Peebles & Xie, 2023), The core idea is straightforward: Instead of the U-Net's complex encoder-decoder, DiT has three stages: patchify the image into a sequence of tokens, process them with standard transformer blocks, and unpatchify back into an image.

Patchify: Image → Sequence

The first step borrows directly from Vision Transformers (ViT). We split the input image into non-overlapping patches, flatten each one, and linearly project it to the model's hidden dimension:

  • Patch size $p$ — typically 2, 4, or 8 pixels
  • A $32 \times 32$ image with $p = 4$ produces $8 \times 8 = 64$ patches
  • Each patch is flattened ($p^2 \times C$ values) and projected to $d_{\text{model}}$
  • Shape: $(B, 3, 32, 32) \rightarrow (B, 64, d_{\text{model}})$ — 64 tokens of dimension $d_{\text{model}}$

We then add 2D positional encodings (learnable or sinusoidal) so each token knows where in the image it came from. Without these, the transformer has no concept of spatial layout — it just sees an unordered bag of tokens.

MNIST Note
MNIST images are $28 \times 28$, which is not evenly divisible by patch size 8. You have several options: use $p = 2$ (giving $14 \times 14 = 196$ patches), $p = 4$ (giving $7 \times 7 = 49$ patches), $p = 7$ (giving $4 \times 4 = 16$ patches), or pad to $32 \times 32$ first. This is a practical detail you'll hit immediately if you try to implement DiT on MNIST.

Transformer Blocks

The middle of DiT is a stack of transformer blocks. Each block has the standard structure you know from NLP and ViT:

  1. Layer normalization
  2. Multi-head self-attention
  3. Residual connection
  4. Layer normalization
  5. Feedforward network (MLP)
  6. Residual connection

The twist is in how we handle conditioning — the timestep and (optionally) class label need to modulate every block. Standard LayerNorm won't cut it. This is where adaLN-Zero comes in, and it's the key innovation that makes DiT work. We'll cover it in detail in the next section.

Unpatchify: Sequence → Image

After all transformer blocks, we need to get back to pixel space. Each token is linearly projected from $d_{\text{model}}$ to $p^2 \times C$ values, then reshaped back into the spatial grid:

$(B, 64, d_{\text{model}}) \rightarrow (B, 3, 32, 32)$

The output is the predicted noise $\hat{\epsilon}$, same as with our U-Net — DiT is a drop-in replacement for the denoiser.

Putting It Together

class DiT: def forward(x, t, class_label=None): # Conditioning embedding c = time_mlp(sinusoidal(t)) # (B, d_model) if class_label is not None: c = c + class_emb(class_label) # add class info # Patchify tokens = patchify(x) # (B, N, d_model) tokens = tokens + pos_encoding # add position info # Transformer blocks for block in self.blocks: tokens = block(tokens, c) # adaLN-Zero conditioning # Unpatchify noise_pred = unpatchify(tokens) # (B, C, H, W) return noise_pred

Conditioning via adaLN-Zero

The challenge is conditioning. A diffusion model needs to know what timestep it's denoising at — the behavior at $t = 10$ (light noise) is completely different from $t = 990$ (nearly pure noise). In our U-Net, we injected timestep information through adaptive group normalization. DiT needs something equivalent for transformer blocks.

From LayerNorm to Adaptive LayerNorm

Standard LayerNorm has two learned parameters, $\gamma$ (scale) and $\beta$ (shift):

$$y = \frac{x - \mu}{\sigma} \cdot \gamma + \beta$$

These parameters are the same regardless of input. Adaptive LayerNorm (adaLN) makes them condition-dependent — we predict $\gamma$ and $\beta$ from the conditioning signal $c$ (timestep + class embedding):

$$\gamma, \beta = \text{Linear}(c)$$

This is the same idea as the adaptive group normalization we used in our U-Net's residual blocks (Lecture 5), just applied to transformer-style LayerNorm instead.

The "Zero" in adaLN-Zero

adaLN-Zero additionally predicts a gate parameter $\alpha$, and initializes it to zero:

$$\gamma, \beta, \alpha = \text{Linear}(c)$$

After each sublayer (attention or FFN), the output is gated:

$$x = x + \alpha \cdot \text{sublayer}(\text{adaLN}(x, \gamma, \beta))$$

Because $\alpha$ starts at zero, every transformer block acts as the identity function at initialization. The model begins by doing nothing — just passing the input through unchanged — and gradually learns to process. This stabilizes training, especially for deep models.

Key Insight
Zero-initialization is a principled approach to training deep residual networks, not an ad hoc trick. By starting each block as an identity, you avoid the "signal explosion" problem where randomly initialized deep networks produce wildly varying outputs. The network starts simple and adds complexity only as needed during training.

DiT Block Pseudocode

class DiTBlock: def forward(x, c): # Predict all adaLN-Zero params from conditioning γ1, β1, α1, γ2, β2, α2 = self.adaln_mlp(c).chunk(6, dim=-1) # Self-attention with adaLN h = layer_norm(x) * (1 + γ1) + β1 h = self_attention(h) x = x + α1 * h # gated residual # FFN with adaLN h = layer_norm(x) * (1 + γ2) + β2 h = ffn(h) x = x + α2 * h # gated residual return x

Notice the symmetry: each block has six condition-dependent parameters — scale, shift, and gate for both the attention sublayer and the FFN sublayer. All six are predicted from a single MLP applied to the conditioning vector $c$.

Why DiT Scales Better

The whole point of moving to transformers was better scaling, and DiT delivers. Let's look at why.

Architectural Simplicity

Compare what you need to define for each architecture:

  • U-Net: encoder stages, decoder stages, channel multipliers at each resolution, which resolutions get attention, skip connection types, number of ResBlocks per stage
  • DiT: number of transformer blocks, hidden dimension, number of attention heads, patch size

With DiT, scaling is trivial: stack more blocks, increase the hidden dimension. No architectural redesign required.

Scaling Results

Peebles and Xie demonstrated clean scaling on ImageNet 256×256 (not MNIST — these are large-scale results):

DiT Scaling (ImageNet 256×256, Classifier-Free Guidance)
  • DiT-S/2 (33M params): FID 68.4
  • DiT-B/2 (130M params): FID 43.5
  • DiT-L/2 (458M params): FID 23.3
  • DiT-XL/2 (675M params): FID 9.62 → with CFG: FID 2.27 (state-of-the-art)

The "/2" means patch size $p = 2$. FID (Fréchet Inception Distance) measures image quality — lower is better.

The pattern is clear: each step up in model size gives a predictable drop in FID. This is the transformer scaling recipe at work — more parameters, more compute, better results, no architecture surgery needed.

U-Net vs. DiT — When to Use Each

DiT doesn't make the U-Net obsolete. Each has its place, and the right choice depends on your constraints.

Property U-Net DiT
Architecture complexity High (many bespoke components) Low (repeated blocks)
Scaling behavior Diminishing returns, needs redesign Follows scaling laws
Multi-resolution Built-in (encoder-decoder) Flat sequence (patch-based)
Skip connections Yes (critical for fine detail) No (relies on deep attention)
Best for Small/medium models, proven recipes Large-scale, frontier models
Used in DDPM, SD 1.5, SDXL Sora, SD 3, Flux

For our MNIST experiments in this course, the U-Net is the right tool — it's smaller, faster to train, and we don't need scaling laws. But if you were building a production image generator? You'd reach for DiT.

DiT in the Wild

DiT powers the most capable generative models shipping today:

  • Sora (OpenAI) — uses DiT for video generation by treating video as spatiotemporal patches. A 10-second video becomes a long sequence of space-time tokens, processed by the same transformer machinery.
  • Stable Diffusion 3 (Stability AI) — replaces the U-Net with an "MM-DiT" (multimodal DiT) that jointly attends to image and text tokens in the same sequence.
  • Flux (Black Forest Labs) — a DiT-based architecture with improved efficiency and quality, from the original Stable Diffusion creators.

The pattern is unmistakable: every new frontier diffusion model is DiT-based, not U-Net-based. The U-Net era (2020–2023) gave way to the DiT era, and the transition happened because transformers do what they always do — scale simply and predictably.

Key Insight
DiT keeps the noise schedules, training objectives, and sampling procedures unchanged. The contribution is showing that the denoiser architecture can be swapped from a bespoke CNN to a standard transformer, inheriting all the scaling benefits that transformers provide. The diffusion framework is architecture-agnostic.

PyTorch Reference

Here's what the key components look like in actual PyTorch. First, the patchify and unpatchify operations:

PyTorch
class Patchify(nn.Module): def __init__(self, patch_size, in_channels, embed_dim): super().__init__() self.proj = nn.Conv2d(in_channels, embed_dim, kernel_size=patch_size, stride=patch_size) def forward(self, x): # x: (B, C, H, W) x = self.proj(x) # (B, embed_dim, H/p, W/p) x = x.flatten(2).transpose(1, 2) # (B, N, embed_dim) return x

And the adaLN-Zero transformer block:

PyTorch
class DiTBlock(nn.Module): def __init__(self, dim, num_heads): super().__init__() self.norm1 = nn.LayerNorm(dim, elementwise_affine=False) self.attn = nn.MultiheadAttention(dim, num_heads, batch_first=True) self.norm2 = nn.LayerNorm(dim, elementwise_affine=False) self.ffn = nn.Sequential( nn.Linear(dim, 4 * dim), nn.GELU(), nn.Linear(4 * dim, dim) ) # Predict 6 adaLN-Zero parameters from conditioning self.adaln = nn.Sequential(nn.SiLU(), nn.Linear(dim, 6 * dim)) # Initialize gate projection to zero nn.init.zeros_(self.adaln[-1].weight) nn.init.zeros_(self.adaln[-1].bias) def forward(self, x, c): # x: (B, N, dim), c: (B, dim) params = self.adaln(c).unsqueeze(1).chunk(6, dim=-1) γ1, β1, α1, γ2, β2, α2 = params # Attention with adaLN-Zero h = self.norm1(x) * (1 + γ1) + β1 h, _ = self.attn(h, h, h) x = x + α1 * h # FFN with adaLN-Zero h = self.norm2(x) * (1 + γ2) + β2 h = self.ffn(h) x = x + α2 * h return x

Looking Ahead

DiT shows that the denoiser architecture is a replaceable module — you can swap the U-Net for a transformer and everything else stays the same. But the "everything else" still includes noise schedules, cumulative alpha products, ELBO-derived losses, and 50–1000 sampling steps.

In the next lecture, we'll ask: what if we could simplify that part too? Flow matching does exactly this — it replaces the entire DDPM framework with straight-line interpolation and velocity prediction. The result is dramatically simpler math, more stable training, and fewer sampling steps. It's the framework behind Stable Diffusion 3 and Flux — and it pairs perfectly with the DiT architecture we just learned.
