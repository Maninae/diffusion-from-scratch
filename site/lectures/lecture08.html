Conditioning & Classifier Guidance

Moving from unconditional to conditional generation: embedding class labels into the U-Net, then steering generation with a trained classifier's gradients.

Conditional Generation Class Embedding Classifier Guidance Historical Context

So far our model generates random images with no user control. To make it useful, we need conditioning, the ability to say "generate a cat sitting on the moon." We'll embed class labels into the U-Net, then discover a more powerful idea: steering generation at sampling time using gradients from a trained classifier, trading diversity for fidelity with a single guidance scale parameter.

This Lecture Is For You If
  • You want to add class labels or other conditioning to a diffusion model
  • You understand the basic unconditional generation pipeline

8.1 From Unconditional to Conditional Generation

Up to now, our diffusion model generates images, but we have no control over what it generates. We get random samples with no way to steer the output. For any practical application, we need to tell the model what to produce: "generate a cat sitting on the moon" or "generate a sunset over the ocean."

The shift is surprisingly simple at the architectural level. Our unconditional model takes two inputs:

$$\epsilon_\theta(x_t, t)$$

A conditional model adds one more — a conditioning signal $c$:

$$\epsilon_\theta(x_t, t, c)$$

The condition $c$ can be almost anything: a class label (integer), a text prompt (sequence of embeddings), another image, video, audio clip, or anything that you can represent as a tensor to feed into the model. For this course, we'll focus on class-conditional generation with class labels, where $c \in \{0, 1, \ldots, K{-}1\}$ for $K$ classes.

Key Insight
The architecture change is minimal: we're adding one more input to the network. The interesting question is how that conditioning signal gets woven into the model's representations, and how we use it during sampling to steer generation.

8.2 Class Embedding & Injection

Now that we've added the conditioning input $c$ to our model's signature, the question is how to represent it. A class label is an integer; it carries no geometric or semantic structure. We need to lift it into a continuous vector that the network can work with. This is the same idea as word embeddings in NLP: map discrete tokens to learned vectors.

The Embedding Lookup

We create a learnable lookup table with one vector per class:

$$\texttt{class\_emb} = \texttt{nn.Embedding}(\texttt{num\_classes}, \texttt{emb\_dim})$$

Given a class label $c$, the embedding layer returns a vector of shape $(\texttt{emb\_dim},)$. This vector is randomly initialized and learned during training. The network discovers what each class "means" in embedding space.

In principle, this embedding vector can come from anywhere: a CLIP encoder, a ResNet trained on ImageNet, a language model. Class labels are the simplest case, but the same injection mechanism generalizes to any conditioning signal that can be represented as a fixed-size vector.

Injection Method 1: Addition to Time Embedding

The simplest and most common approach: add the class embedding directly to the time embedding before the MLP. The network receives a single conditioning vector that encodes both when in the diffusion process we are and what class we're generating:

$$\texttt{combined\_emb} = \texttt{time\_emb}(t) + \texttt{class\_emb}(c)$$

This works well for class-conditional generation and is what we'll implement. Both embeddings have the same dimensionality, so the addition is element-wise.

Alternative Injection Methods

  • Separate injection: Process the class embedding through its own MLP, then add it to features at each ResBlock independently from the time embedding. More expressive, but more parameters.
  • Adaptive Group Normalization (AdaGN): Use the conditioning vector to predict per-channel scale and shift parameters for GroupNorm. This is the most expressive approach, used in DALL-E 2 and other advanced architectures.
  • Cross-attention: For conditions richer than a single vector, such as text prompts (sequences of token embeddings) or image-shaped inputs, architectures like Stable Diffusion inject conditioning through cross-attention layers. The model attends to the conditioning sequence at every block, allowing it to extract spatial or semantic features on the fly.
  • And more: Concatenation along the channel axis (DiT patchifies the noisy image and concatenates conditioning tokens directly into the input sequence), hypernetworks that generate layer weights from the condition, ControlNet-style parallel branches for spatial control. As long as the conditioning signal is a tensor, there is a way to feed it into the network. New injection methods continue to appear as the field evolves.

Four different modalities, four different tensor shapes, one unified entry point. The trick isn't in the model — it's in converting each input into a tensor and injecting it through one of the mechanisms above.

The Null Class Token

One important detail: we allocate one extra class in our embedding table. If we have 10 digit classes (0–9), we create an embedding of size 11. Index 10 is the null class — it means "no conditioning": no additional information hinting at what to produce, as if conditioning were never applied.

This will become critical in Lecture 9 when we implement classifier-free guidance, which requires the model to make predictions both with and without a class label.

Conditional U-Net Architecture class ConditionalUNet(UNet): def __init__(self, num_classes, ...): # +1 for null class token (index = num_classes) # "no class" enables unconditional prediction from same model self.class_emb = Embedding(num_classes + 1, emb_dim) def forward(self, x_t, t, class_label=None): t_emb = self.time_mlp(sinusoidal_embedding(t)) # (B, emb_dim) if class_label is not None: c_emb = self.class_emb(class_label) # (B, emb_dim) t_emb = t_emb + c_emb # combine # Rest of U-Net forward pass uses t_emb as before ...

8.3 Training the Conditional Model

The good news: training is nearly identical to what we did in Lecture 6. Each training sample now includes a label alongside the image: $(x_0, c)$. The label gets embedded and integrated into the time embedding, such as by addition. The loss function is unchanged:

$$\mathcal{L} = \|\epsilon - \epsilon_\theta(x_t, t, c)\|^2$$

The model learns to make class-specific noise predictions. When told "this is class A at noise level $t$," it predicts the noise differently than when told "this is class B at noise level $t$."

At high noise levels, images from different classes look nearly identical: mostly static. Without conditioning, the model has to guess which class it's denoising. The class label removes that guesswork, telling the model exactly what structure to recover from the noise.

Conditional Training Step def train_step(model, x_0, class_label, optimizer, schedule): t = random_integers(0, T-1, batch_size) noise = randn_like(x_0) x_t = q_sample(x_0, t, noise, schedule) noise_pred = model(x_t, t, class_label) # now with class! loss = mse_loss(noise_pred, noise) loss.backward() optimizer.step()
Key Insight
Minimal change from unconditional training. Compare this to the unconditional training step from Lecture 6 — the only difference is passing class_label to the model. The loss, the noise sampling, the forward diffusion process: all identical. The conditioning is handled entirely by the architecture change.

8.4 Classifier Guidance (Historical Context)

Can we amplify how much the model pays attention to its conditioning during sampling? Dhariwal & Nichol (2021) proposed classifier guidance—using gradients from a separately trained classifier to steer the denoising direction toward a target class. It was later superseded by the simpler classifier-free guidance (CFG) approach in Lecture 9, but understanding the original idea clarifies why CFG was such an improvement.

Definition
Classifier Guidance. Train a separate classifier $\htmlData{tip=A separately trained classifier predicting the probability of class y from noisy image x_t}{p_\phi(y \mid x_t)}$ on noisy images at all noise levels. During sampling, use its gradients to steer the denoising process toward the desired class.

How It Works

The idea is intuitive: at each denoising step, we ask a classifier "which direction should I move $x_t$ to make it look more like class $y$?"

The answer is a gradient computed with respect to the pixels of $x_t$: $\nabla_{x_t} \log p_\phi(y \mid x_t)$. This is a tensor the same shape as the image, where each entry tells us how to nudge each pixel to increase the classifier's confidence in class $y$. We then add this gradient into the model's noise prediction, effectively biasing the denoising step so that $x_{t-1}$ lands closer to the target class than a purely unconditional step would.

Concretely, at each step of the reverse process:

  1. Predict noise as usual: $\epsilon_\theta(x_t, t)$
  2. Compute classifier gradient: $\nabla_{x_t} \log p_\phi(y \mid x_t)$ — "which direction makes $x_t$ look more like class $y$?"
  3. Shift the noise prediction: $$\hat{\epsilon} = \epsilon_\theta - s \cdot \sqrt{1 - \bar{\alpha}_t} \cdot \nabla_{x_t} \log p_\phi(y \mid x_t)$$
  4. Use $\hat{\epsilon}$ for the standard DDPM denoising step
Why a minus sign?

The formula subtracts the classifier gradient, which looks backwards at first. After all, the gradient $\nabla_{x_t} \log p(y \mid x_t)$ points in the direction that makes $x_t$ look more like class $y$. Shouldn't we add it?

The resolution is that $\epsilon_\theta$ is the noise we subtract during denoising. The update looks roughly like $x_{t-1} \approx x_t - (\text{coeff}) \cdot \hat{\epsilon}$. So subtracting the classifier gradient from $\hat{\epsilon}$ means the denoiser effectively adds that gradient to the update direction. Two minus signs cancel: subtract from the noise, subtract the noise from $x_t$, net effect is a push toward class $y$.

Formally, this follows from the score-matching identity $\epsilon_\theta \approx -\sigma_t \cdot \nabla_{x_t} \log p(x_t)$: the noise prediction points opposite to the score. Applying Bayes' rule to get a conditional score ($\nabla \log p(x_t \mid y) = \nabla \log p(x_t) + \nabla \log p(y \mid x_t)$) and converting back to noise produces exactly the formula above, minus sign and all.

The parameter $s$ is the guidance scale. It controls how strongly the classifier steers. In concrete terms, a larger $s$ means each denoising step takes a bigger detour toward whatever the classifier thinks class $y$ looks like, at the cost of ignoring other plausible image structures:

  • $s = 0$: no guidance, pure unconditional generation
  • $s = 1$: standard classifier guidance
  • $s > 1$: amplified guidance, sharper and more class-specific images, but less diversity
Classifier guidance shifts the denoising direction by subtracting a scaled classifier gradient. The guidance scale s controls how strongly the prediction is pulled toward the target class. At s = 0, we get unconditional denoising; at high s, the classifier gradient dominates, producing sharper but less diverse samples.

What Distribution Are We Sampling From?

The gradient-based steering we just described has a clean interpretation in terms of probability distributions. Mathematically, classifier guidance causes us to sample from a sharpened distribution:

$$p_\text{guided}(x \mid y) \propto p(x) \cdot p(y \mid x)^s$$

When $s = 1$, this is just Bayes' rule, giving the standard conditional $p(x \mid y)$. When $s > 1$, we raise the classifier likelihood to a power, which sharpens the distribution around images that the classifier confidently assigns to class $y$. Think of it like adjusting the contrast on a probability landscape: at $s = 1$, the distribution has gentle hills and valleys across all plausible images of class $y$. Cranking $s$ to 5 or 10 turns those hills into narrow spikes, concentrating almost all probability mass on the few images the classifier is most confident about. The generated samples become crisper and more stereotypical, but the model loses the ability to produce unusual or creative variations. Higher $s$ means sharper peaks but thinner tails: better fidelity, less diversity.

Sampling with Classifier Guidance

Classifier-Guided Sampling def classifier_guided_sample(model, classifier, class_label, schedule, s): x = randn(shape) # start from noise for t in reversed(range(T)): # 1. Standard noise prediction noise_pred = model(x, t) # 2. Classifier gradient x.requires_grad_(True) log_prob = classifier(x, t).log_softmax(dim=-1)[:, class_label] grad = autograd.grad(log_prob.sum(), x)[0] x.requires_grad_(False) # 3. Shift noise prediction toward desired class noise_pred = noise_pred - s * sqrt(1 - alpha_bar[t]) * grad # 4. Standard DDPM step with modified prediction x = ddpm_step(x, noise_pred, t, schedule) return x

8.5 Why Classifier Guidance Falls Short

At this point, classifier guidance has delivered on its promise: we can steer a diffusion model toward a target class at sampling time, and the results are visibly sharper than unconditional generation.

So why not stop here? Because the machinery required to get those results introduces problems of its own.

  • You have to train a whole extra model. The classifier must handle noisy images at all noise levels, from nearly-clean ($t \approx 0$) to pure static ($t \approx T$). That is an expensive, non-trivial training task on its own.
  • Every new condition type needs a new classifier. Want to condition on text instead of class labels? You need to train an entirely different classifier. Each new conditioning modality requires its own external model.
  • Sampling gets slower. At every denoising step, you must compute gradients through the classifier via backpropagation. This is significantly slower than a simple forward pass.
  • Rich conditioning is out of reach. The approach does not naturally extend to complex conditioning signals like text prompts, which require understanding semantics rather than simple classification.
Key Insight

Classifier guidance proved that external signals can steer diffusion models during sampling. The limitation is practical: training a separate classifier for every conditioning type is expensive and inflexible. What if the guidance signal could come from the diffusion model itself? That is exactly what classifier-free guidance achieves, as we will see in Lecture 9.

8.6 PyTorch Reference

Here's how the conditional U-Net modification looks in real PyTorch. The key change from our unconditional model is just three lines: embedding initialization, embedding lookup, and the addition.

PyTorch import torch import torch.nn as nn class ConditionalUNet(nn.Module): def __init__(self, in_ch, out_ch, time_dim=256, num_classes=10): super().__init__() # ... existing U-Net layers ... # +1 for null class token used in CFG (Lecture 9) self.class_emb = nn.Embedding(num_classes + 1, time_dim) def forward(self, x, t, class_label=None): t_emb = self.time_mlp(self.sinusoidal_embedding(t)) # (B, time_dim) if class_label is not None: c_emb = self.class_emb(class_label) # (B, time_dim) t_emb = t_emb + c_emb # fuse conditioning # Forward pass uses t_emb exactly as before # Every ResBlock receives the same combined embedding ...

And the classifier guidance sampling loop in PyTorch:

PyTorch @torch.no_grad() def classifier_guided_sample(model, classifier, y, schedule, guidance_scale=3.0): x = torch.randn(batch_size, 1, 28, 28, device=device) for t in reversed(range(T)): t_batch = torch.full((batch_size,), t, device=device) # Noise prediction (no grad needed) noise_pred = model(x, t_batch) # Classifier gradient (grad needed for x only) with torch.enable_grad(): x_in = x.detach().requires_grad_(True) logits = classifier(x_in, t_batch) log_probs = logits.log_softmax(dim=-1) selected = log_probs[range(batch_size), y] grad = torch.autograd.grad(selected.sum(), x_in)[0] # Shift noise prediction alpha_bar_t = schedule['alphas_cumprod'][t] noise_pred = noise_pred - guidance_scale * (1 - alpha_bar_t).sqrt() * grad # Standard DDPM update step x = ddpm_step(x, noise_pred, t, schedule) return x
