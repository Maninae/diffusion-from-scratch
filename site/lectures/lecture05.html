Time Conditioning & Spatial Attention

Sinusoidal timestep embeddings, time injection into ResBlocks, and self-attention that gives the network a global receptive field, completing the U-Net architecture.

Time Embedding Sinusoidal Encoding Self-Attention AdaGN
← U-Net: Encoder, Decoder & Skips Training a Diffusion Model →

Our U-Net can denoise, but it doesn't know how much noise it's looking at. Denoising at $t = 10$ and $t = 990$ are fundamentally different tasks, yet the network treats them identically. We'll fix that with sinusoidal timestep embeddings borrowed from transformers, inject them into every ResBlock, and then add self-attention so the network can coordinate distant spatial regions — completing the architecture.

This Lecture Is For You If
  • You want to know how the network distinguishes between noise levels and captures global structure
  • You've seen sinusoidal encodings or attention mechanisms before, or are ready to learn them

5.1 Why the Network Needs to Know t

The U-Net from Lecture 4 can take a noisy image and produce a noise prediction. But right now, it's blind to an absolutely critical piece of information: how much noise is in the image.

Consider three different scenarios:

  • $t = 10$: The image is nearly clean. Only a faint haze of noise has been added. The network should make tiny, careful corrections. Most of the image is already signal.
  • $t = 500$: Half signal, half noise. The underlying image is visible but degraded. The network must separate genuine structure from noise at every pixel.
  • $t = 990$: Almost pure Gaussian static. The original image is essentially destroyed. The network must hallucinate plausible structure from nearly zero signal.

These are fundamentally different tasks. A network that doesn't know the current timestep would produce the same prediction regardless of noise level, and that prediction would be wrong for almost every $t$.

We need to inject a representation of the timestep into every layer of the network.

Key Insight
Time conditioning is what turns a single network into a family of denoisers, one for each noise level. The same weights handle all 1000 timesteps, but the time embedding modulates the network's behavior at each one.

5.2 Sinusoidal Timestep Embeddings

We could pass the timestep as a raw scalar, concatenate $t$ to the input or feed it as an extra feature. But a single number doesn't give the network enough structure to modulate its behavior across hundreds of distinct noise levels. We need a high-dimensional, structured representation of each timestep.

The solution is sinusoidal positional encoding, borrowed from transformers (Vaswani et al., 2017). The same formula that encodes token positions in a sequence can encode noise levels for a U-Net.

The Formula

Given a timestep $t$ and an embedding dimension $d$, the sinusoidal embedding is:

$$\text{emb}[2i] = \sin\!\left(\frac{t}{10000^{2i/d}}\right), \qquad \text{emb}[2i+1] = \cos\!\left(\frac{t}{10000^{2i/d}}\right)$$

for $i = 0, 1, \ldots, d/2 - 1$. Each pair of dimensions oscillates at a different frequency:

  • Low dimensions ($i$ small): high frequency — oscillates rapidly, capturing fine distinctions between nearby timesteps.
  • High dimensions ($i$ large): low frequency — oscillates slowly, capturing the broad "early vs. late" distinction.

There's a clean geometric intuition here. Each adjacent pair of indices $(2i, 2i{+}1)$ in the embedding encodes a $(\sin, \cos)$ pair at the same frequency, which is equivalent to a point on a unit circle at angle $\theta_i = t / 10000^{2i/d}$. As $t$ increases, each pair rotates around its circle. Low-frequency pairs (small $i$) rotate slowly, completing one revolution over thousands of timesteps. High-frequency pairs (large $i$) spin fast, cycling many times before $t$ reaches 1000.

The result is a unique "fingerprint" for every timestep, a vector in $\mathbb{R}^d$ where nearby timesteps have similar (but distinct) embeddings, and distant timesteps have very different embeddings.

Example
With $d = 128$, the sinusoidal embedding maps each integer $t$ to a 128-dimensional vector. The embedding for $t = 500$ is close to the embedding for $t = 501$ (the denoising task is similar), but far from the embedding for $t = 50$ (the denoising task is very different). This smoothness is exactly what we want; the network's behavior should change gradually as $t$ varies.
Sinusoidal Timestep Embedding
def sinusoidal_embedding(t, dim):
    half_dim = dim // 2
    frequencies = 1 / (10000 ** (range(half_dim) / half_dim))
    angles = t[:, None] * frequencies[None, :]   # (B, half_dim)
    embedding = concat(sin(angles), cos(angles), dim=-1)  # (B, dim)
    return embedding

Input: a batch of integer timesteps, shape $(B,)$. Output: a batch of embedding vectors, shape $(B, d)$. No spatial dimensions; this is a single vector per sample.

5.3 The Time MLP

The raw sinusoidal embedding is a fixed, deterministic function with no learnable parameters. To give the network flexibility in how it uses the timestep information, we pass the embedding through a small MLP:

$$t \;\xrightarrow{\text{sinusoidal}}\; \mathbb{R}^d \;\xrightarrow{\text{Linear}}\; \mathbb{R}^{4d} \;\xrightarrow{\text{SiLU}}\; \mathbb{R}^{4d} \;\xrightarrow{\text{Linear}}\; \mathbb{R}^{4d}$$

The MLP learns to transform the raw sinusoidal features into whatever representation is most useful for the downstream ResBlocks. The expansion to $4d$ gives the MLP enough capacity to learn complex, nonlinear functions of the timestep.

TimestepMLP
class TimestepMLP:
    def forward(t):
        emb = sinusoidal_embedding(t, base_dim)    # (B, base_dim)
        emb = linear_1(emb)                         # (B, 4 * base_dim)
        emb = silu(emb)
        emb = linear_2(emb)                         # (B, 4 * base_dim)
        return emb

This MLP is computed once per forward pass, and the resulting time embedding is shared across all ResBlocks in the network.

5.4 Injecting Time into ResBlocks

Now we have a rich time embedding vector of shape $(B, C_\text{emb})$. How do we get it into the convolutional layers that operate on feature maps of shape $(B, C, H, W)$? There are two main approaches.

Method 1: Additive Injection

The simplest approach: project the time embedding to match the channel count, then add it to the feature map after the first convolution. The time vector is broadcast over the spatial dimensions $H$ and $W$.

# Inside ResBlock — additive time injection
h = conv1(silu(group_norm1(x)))          # (B, C, H, W)
time_proj = linear(time_emb)              # (B, C_emb) → (B, C)
h = h + time_proj[:, :, None, None]       # broadcast over H, W
h = conv2(silu(group_norm2(h)))           # (B, C, H, W)

This is the method used in the original DDPM. The [:, :, None, None] adds two dimensions to turn $(B, C)$ into $(B, C, 1, 1)$, which PyTorch broadcasts to match $(B, C, H, W)$. The same time signal is added to every spatial position.

Method 2: Scale-Shift (AdaGN)

A more expressive approach: predict both a scale $\gamma$ and a shift $\beta$ from the time embedding, then modulate the features after GroupNorm:

$$y = (1 + \gamma) \cdot \text{GroupNorm}(h) + \beta$$

where $[\gamma, \beta] = \text{Linear}(\text{time\_emb})$, each of shape $(B, C)$.

# Inside ResBlock — scale-shift (AdaGN) time injection
h = conv1(silu(group_norm1(x)))                        # (B, C, H, W)
scale, shift = linear(time_emb).chunk(2, dim=1)        # each (B, C)
h = group_norm2(h) * (1 + scale[:,:,None,None]) + shift[:,:,None,None]
h = conv2(silu(h))                                     # (B, C, H, W)

Why is this more expressive? With additive injection, the time signal can only shift feature values. With scale-shift, it can also amplify or suppress entire channels. The network might learn to turn off certain feature channels at high noise levels and activate them at low noise levels.

Definition
Adaptive Group Normalization (AdaGN). A conditioning mechanism where an external signal (here, the timestep) predicts per-channel scale and shift parameters that modulate the output of GroupNorm. Introduced by Dhariwal & Nichol (2021) in their "Diffusion Models Beat GANs" paper, where it led to measurable improvements in image quality.

5.5 The Complete ResBlock with Time

Combining what we've covered, here's the complete data flow through a single ResBlock with time conditioning:

  1. First half: GroupNorm → SiLU → Conv
  2. Time injection: project time embedding, add (or scale-shift) into features
  3. Second half: GroupNorm → SiLU → Dropout → Conv
  4. Residual: add shortcut connection (1×1 conv if channels change)
ResBlock with Time Embedding
class ResBlock:
    def forward(x, time_emb):
        h = conv1(silu(group_norm1(x)))             # (B, C_out, H, W)
        h = h + time_proj(silu(time_emb))[:,:,None,None]  # inject time
        h = conv2(dropout(silu(group_norm2(h))))     # (B, C_out, H, W)
        return h + shortcut(x)                       # residual connection

This is the core building block. The entire U-Net is built by stacking these ResBlocks, two per encoder level and two per decoder level. Every ResBlock receives the same time embedding, so every layer of the network is time-aware.

5.6 Where Attention Goes in the U-Net

Convolutions are inherently local: a 3×3 kernel sees only its immediate neighborhood. For denoising, we often need global context: "the top-left of this digit should be consistent with the bottom-right." Self-attention provides this global receptive field, but it comes at a steep computational cost.

The Quadratic Cost Problem

Self-attention is $O(n^2)$ where $n = H \times W$ is the number of spatial tokens. The attention matrix has $n^2$ entries:

  • At $7 \times 7$: $n = 49$ tokens, attention matrix = $2{,}401$ entries — trivially cheap
  • At $14 \times 14$: $n = 196$ tokens, attention matrix $\approx 38$K entries — cheap
  • At $28 \times 28$: $n = 784$ tokens, attention matrix $\approx 615$K entries — feasible
  • At $256 \times 256$: $n = 65{,}536$ tokens, attention matrix $\approx 4.3$ billion entries — infeasible

This is why attention is used strategically, not everywhere:

  • Original DDPM: attention only at $16 \times 16$ resolution
  • Improved DDPM / ADM: attention at $32 \times 32$, $16 \times 16$, and $8 \times 8$
  • Our MNIST model: attention at $7 \times 7$ (bottleneck) — cheap and effective
Note
The quadratic cost of attention is one reason why high-resolution diffusion models use latent diffusion (Lecture 10). By operating in a compressed latent space ($32 \times 32$ or $64 \times 64$), attention becomes computationally feasible even for 512×512 images.

5.7 Spatial Self-Attention

Images aren't sequences, but we can reshape them into one. The core trick of spatial self-attention: treat each spatial position $(h, w)$ as a "token" and apply standard multi-head self-attention.

Step by Step

  1. Normalize: apply GroupNorm to the feature map (normalize before attention, not after)
  2. Reshape: $(B, C, H, W) \to (B, H \times W, C)$ — each spatial position becomes a token with $C$ features
  3. Attend: apply multi-head self-attention on the sequence of $H \times W$ tokens
  4. Reshape back: $(B, H \times W, C) \to (B, C, H, W)$ — fold tokens back into a spatial grid
  5. Residual: add the original input (the attention output is a correction)

The Attention Formula

Each attention head computes:

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

where $Q$, $K$, $V$ are linear projections of the input tokens, and $d_k$ is the dimension per head. The $\sqrt{d_k}$ scaling prevents the dot products from growing too large as the dimension increases (which would push the softmax into saturation, killing gradients).

Example
At our $7 \times 7$ bottleneck with 256 channels and 4 attention heads: each token has $256 / 4 = 64$ features per head. The attention matrix is $49 \times 49$ per head. Token at position $(3, 5)$ can directly attend to token at position $(0, 0)$ — a global receptive field in a single layer, something that would require stacking many 3×3 convolutions to achieve.
Spatial Self-Attention
class SpatialSelfAttention:
    def forward(x):
        B, C, H, W = x.shape
        h = group_norm(x)                                # normalize first
        h = h.reshape(B, C, H*W).transpose(1, 2)        # (B, H*W, C)
        attn_out = multi_head_attention(h, h, h)         # (B, H*W, C)
        attn_out = attn_out.transpose(1, 2).reshape(B, C, H, W)
        return x + attn_out                              # residual connection

Note the residual connection: the attention output is added to the original input. This means attention acts as a refinement. The feature map already has useful information from the convolutions, and attention adds global context on top.

5.8 Cross-Attention Preview

Everything we've discussed so far is self-attention: the query, key, and value all come from the same feature map. But there's a powerful variant used in conditional generation.

In cross-attention, the queries still come from the image features, but the keys and values come from an external conditioning signal — like a text embedding from CLIP. This is exactly how Stable Diffusion injects text prompts into the U-Net: the image features "ask questions" (queries) about the text (keys and values).

  • Self-attention: $Q, K, V$ all from image features — "how do different parts of this image relate to each other?"
  • Cross-attention: $Q$ from image, $K, V$ from text — "what does the text tell us about this region of the image?"

We'll cover cross-attention in detail in Lecture 9. For now, the mechanism is identical; the only difference is where $K$ and $V$ come from.

5.9 The Complete U-Net — All Pieces Connected

Let's assemble everything we've built across Lectures 4 and 5 into the complete architecture:

  1. Initial conv: image_channels → base_channels
  2. Time embedding: $t \xrightarrow{\text{sinusoidal}} \mathbb{R}^d \xrightarrow{\text{MLP}} \mathbb{R}^{4d}$
  3. Down blocks: [ResBlock(+time), ResBlock(+time), (optional Attention), Downsample] × $N$
  4. Middle: ResBlock(+time) → Attention → ResBlock(+time)
  5. Up blocks: [Upsample, concat skip, ResBlock(+time), ResBlock(+time), (optional Attention)] × $N$
  6. Final: GroupNorm → SiLU → Conv → image_channels

The forward signature: model(x_t, t) → noise_pred, where $x_t$ is the noisy image at timestep $t$ and the output is $\varepsilon_\theta(x_t, t)$ — the predicted noise. Optionally, model(x_t, t, class_label) for conditional generation (Lecture 8).

Where Do the Parameters Live?

Not all parts of the U-Net are created equal in terms of parameter count:

  • Lower-resolution blocks (128 and 256 channels) contain the bulk of parameters, since convolutions with more channels have quadratically more weights.
  • Attention layers add significant parameters at each resolution where they're applied.
  • The time MLP is relatively small, typically a few thousand parameters.
  • Higher-resolution blocks (64 channels) are cheap per-block but process the largest feature maps, so they dominate compute time.
Key Insight
The U-Net concentrates its representational capacity at low resolutions (many channels, attention) where the computational cost per operation is low, and keeps high-resolution processing lightweight (fewer channels, no attention). This balances model expressiveness against computational efficiency.

5.10 Putting It to the Test

We can now verify that our complete U-Net produces output with the correct shape:

from utils.unet import UNet
import torch

model = UNet(
    in_channels=1,
    base_channels=64,
    channel_mults=(1, 2, 4),
    num_res_blocks=2,
    time_emb_dim=256,
    attention_resolutions=(7,),     # attention at 7×7 only
)

# Count parameters
n_params = sum(p.numel() for p in model.parameters())
print(f"Parameters: {n_params:,}")   # ~7M for this config

# Verify input/output shapes match
x_t = torch.randn(4, 1, 28, 28)
t = torch.randint(0, 1000, (4,))
noise_pred = model(x_t, t)

assert noise_pred.shape == x_t.shape
print(f"Input:  {tuple(x_t.shape)}")        # (4, 1, 28, 28)
print(f"Output: {tuple(noise_pred.shape)}")  # (4, 1, 28, 28) — same!

The network is ready. It takes a noisy image and a timestep, and outputs a noise prediction of the same shape. In Lecture 6, we'll use this architecture to actually train a diffusion model, implementing the DDPM training algorithm from scratch and watching it learn to denoise MNIST digits.
