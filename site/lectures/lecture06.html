6.1 From Math to Working Code

We have the math from Lecture 3: a loss function, a forward noising process, and a six-line training algorithm. We have the architecture from Lectures 4–5: a U-Net with time conditioning and attention. In principle, we could just wire them together and start training. In practice, doing that naively will produce a model that trains painfully slowly, generates blurry mush, or quietly diverges at step 5,000.

This lecture is about the practical engineering that turns Algorithm 1 into a pipeline that actually works.

None of these techniques are optional extras. They're the difference between generating recognizable images in 5K steps and generating noise at 50K steps.

Key Insight
Training a diffusion model is hard because dozens of small decisions (normalization range, optimizer, learning rate, weight averaging) interact in subtle ways, and getting any one of them wrong can silently degrade quality.

6.2 Data Loading & Preprocessing

Normalize to [−1, 1], Not [0, 1]

This is the single most common mistake in diffusion model implementations. Your model predicts noise $\epsilon \sim \mathcal{N}(0, I)$, values that are mean-zero and symmetric around the origin.

If your images live in $[0, 1]$, you've introduced an asymmetry: the model has to learn to predict symmetric noise from an asymmetric signal. It works, but it's harder than it needs to be.

The fix is simple: normalize images to $[-1, 1]$. The transform pipeline is:

transform = Compose([ ToTensor(), # [0, 255] → [0, 1] Normalize([0.5], [0.5]), # [0, 1] → [-1, 1] ]) dataset = MNIST(root='./data', train=True, transform=transform) dataloader = DataLoader(dataset, batch_size=64, shuffle=True)

When you want to display images, you reverse it: $x_{\text{display}} = (x + 1) / 2$, mapping back to $[0, 1]$. Our denormalize() utility handles this.

Data Augmentation: Less Than You'd Think

For MNIST, we use no data augmentation. This might surprise you, since augmentation is standard practice in classification. But here's the thing: horizontal flips would destroy digit identity. A flipped 3 or 7 becomes unrecognizable; a flipped 6 becomes a 9.

And diffusion training already provides powerful implicit augmentation: each image is seen at thousands of different noise levels across training, effectively multiplying the dataset many times over.

Example
Implicit augmentation in diffusion. A single MNIST digit seen at timesteps $t = 10, 100, 500, 900$ looks like four completely different training examples — from nearly clean to nearly pure noise. Over 20K training steps with batch size 64, each image is seen at ~20 random noise levels. That's far more variety than a horizontal flip would provide.

6.3 The Training Loop — Algorithm 1 in Code

Let's expand the six-line DDPM training algorithm into real, working code. Each line of the algorithm maps to a concrete operation with specific shapes and device requirements.

Algorithm 1 — DDPM Training (Ho et al., 2020)
  1. repeat
  2. $\mathbf{x}_0 \sim q(\mathbf{x}_0)$ — sample a batch of clean images
  3. $t \sim \text{Uniform}(\{1, \ldots, T\})$ — sample random timesteps
  4. $\boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$ — sample noise
  5. Take gradient step on $\nabla_\theta \left\| \boldsymbol{\epsilon} - \boldsymbol{\epsilon}_\theta\!\left(\sqrt{\bar{\alpha}_t}\, \mathbf{x}_0 + \sqrt{1-\bar{\alpha}_t}\, \boldsymbol{\epsilon},\; t\right) \right\|^2$
  6. until converged

The complete training step:

def train_step(model, x_0, optimizer, schedule, device): # 1. Sample random timesteps — one per image in the batch t = randint(0, T-1, size=batch_size).to(device) # 2. Sample noise noise = randn_like(x_0) # (B, 1, 28, 28) # 3. Create noisy images using closed-form q(x_t | x_0) sqrt_alpha_bar = schedule.sqrt_alphas_cumprod[t] # (B,) sqrt_one_minus = schedule.sqrt_one_minus_alphas_cumprod[t] # (B,) # Reshape for broadcasting: (B,) → (B, 1, 1, 1) x_t = sqrt_alpha_bar[:, None, None, None] * x_0 + sqrt_one_minus[:, None, None, None] * noise # (B, 1, 28, 28) # 4. Predict noise noise_pred = model(x_t, t) # (B, 1, 28, 28) # 5. Compute loss loss = mse_loss(noise_pred, noise) # 6. Update weights optimizer.zero_grad() loss.backward() clip_grad_norm(model.parameters(), max_norm=1.0) optimizer.step() return loss.item()

A critical implementation detail: the schedule tensors (sqrt_alphas_cumprod, etc.) must live on the same device as your model. Use prepare_schedule() from utils/schedule.py to move everything at once.

Definition
The training loss. The simplified DDPM objective is: $$L_{\text{simple}} = \mathbb{E}_{t, \mathbf{x}_0, \boldsymbol{\epsilon}}\left[ \left\| \boldsymbol{\epsilon} - \boldsymbol{\epsilon}_\theta\!\left(\sqrt{\bar{\alpha}_t}\, \mathbf{x}_0 + \sqrt{1-\bar{\alpha}_t}\, \boldsymbol{\epsilon},\; t\right) \right\|^2 \right]$$ In words: sample a clean image, add noise at a random timestep, predict the noise, and minimize the squared error between the predicted and actual noise.

6.4 Timestep Sampling Strategies

Algorithm 1 says "sample $t$ uniformly." This is the standard approach and works well, but it's worth understanding why it's suboptimal, and what alternatives exist.

Uniform Sampling

The default: t = torch.randint(0, T, (batch_size,)). Each image in the batch gets an independent random timestep. Simple, effective, and what DDPM uses.

Why Uniform Is Suboptimal

Not all timesteps are equally informative. Consider what the model sees at different noise levels:

  • Low $t$ (little noise): the image is nearly clean. Predicting the (small amount of) noise is easy; the model barely needs to do anything. Loss is small, gradients are uninformative.
  • High $t$ (lots of noise): the image is nearly pure Gaussian noise. The model can't see the underlying image at all, so it's essentially predicting random noise from random noise. Also relatively easy in terms of loss magnitude.
  • Mid $t$: the hardest range. The signal is partially visible but heavily corrupted. The model has to work hard to separate signal from noise. These timesteps produce the most informative gradients.

Uniform sampling wastes half its compute on easy timesteps at the extremes.

Importance Weighting (P2)

P2 weighting (Perception Prioritized, Choi et al. 2022) reweights the loss by $1/(1 + \text{SNR}(t))$, which upweights mid-noise timesteps where the gradients are most useful. This improves FID scores, especially on complex datasets like CIFAR-10 and ImageNet.

Practical advice: start with uniform sampling. It's simpler and works well for MNIST. Switch to importance weighting if you're training on harder datasets and want to squeeze out better FID.

6.5 Gradient Clipping

Diffusion training loss can spike, especially in the first few hundred steps when the model is still learning basic structure, or when an unlucky batch happens to contain all high-noise timesteps. Without protection, a single bad batch can produce enormous gradients that blow up your model weights.

The fix is gradient clipping:

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

This computes the total $L_2$ norm of all gradients across all parameters. If the norm exceeds 1.0, every gradient is rescaled proportionally so the total norm is exactly 1.0. The direction of the update is preserved; only the magnitude is capped.

Key Insight
Gradient clipping doesn't change the direction of the optimization step; it only prevents catastrophically large steps. Think of it as a speed limit: the optimizer can go anywhere, but it can't go there too fast. This is standard practice in essentially all modern diffusion training.

6.6 EMA — Exponential Moving Average

This may seem counterintuitive, but the best weights for generating samples are not the current training weights. They're a smoothed average of all recent training weights.

Why EMA Helps

During training, model weights oscillate around the optimum, overshooting in one direction, then correcting. These oscillations are fine for computing gradients (the optimizer handles them), but they produce noisy, inconsistent samples. EMA averages out the oscillations, yielding a smoother set of weights that generates higher-quality images.

The update rule is:

$$\theta_{\text{ema}} = \lambda \cdot \theta_{\text{ema}} + (1 - \lambda) \cdot \theta$$

With $\lambda = 0.9999$ (the standard decay), the EMA model changes very slowly. Each training step nudges it by just 0.01% toward the current weights. This heavy smoothing is what makes EMA so effective.

Implementation

class EMA: def __init__(self, model, decay=0.9999): self.shadow = deepcopy(model.parameters()) self.decay = decay def update(self, model): for ema_param, model_param in zip(self.shadow, model.parameters()): ema_param.data = self.decay * ema_param + (1 - self.decay) * model_param def apply_to(self, model): # Temporarily swap in EMA weights for sampling ...
Definition
EMA (Exponential Moving Average). A shadow copy of model parameters, updated after each training step as $\theta_{\text{ema}} \leftarrow 0.9999 \cdot \theta_{\text{ema}} + 0.0001 \cdot \theta$. Use EMA weights for sampling and evaluation. Use regular weights for gradient computation and optimizer updates. Never compute gradients through the EMA model.

6.7 Learning Rate Schedule

The learning rate controls how big each optimizer step is. Getting this right has an outsized effect on training stability and convergence speed.

Linear Warmup

For the first 1,000 steps, linearly increase the learning rate from 0 to the target value (e.g., $2 \times 10^{-4}$). Why? In the first few steps, the model knows nothing, and its predictions are random noise. Large learning rates at this point cause wild parameter swings. Warmup lets the model establish basic structure before the optimizer starts making aggressive updates.

Cosine Decay

After warmup, the learning rate follows a cosine curve from the target value down to 0. This schedule is gentle: it holds near the peak for a long time, then gradually decreases as training matures. It's the default in most modern training pipelines.

The Practical Recipe

For MNIST, the simplest approach works fine: Adam with a constant learning rate of $2 \times 10^{-4}$. This is what the original DDPM paper used, and for a small dataset like MNIST it's all you need.

For more complex datasets (CIFAR-10, ImageNet), the full recipe is: AdamW with $\text{lr} = 2 \times 10^{-4}$, linear warmup for 1,000 steps, cosine decay to 0. AdamW adds decoupled weight decay regularization, which is modern best practice.

6.8 Common Training Pitfalls

Diffusion models fail in predictable ways. The most common failure modes and their fixes.

Loss Spikes

Symptom: Loss suddenly jumps to 10× its normal value, then (hopefully) recovers. Cause: Gradient explosion from an unlucky batch. Fix: Gradient clipping with max_norm=1.0. If spikes persist, reduce the learning rate.

Loss Plateau at Start

Symptom: Loss stays flat for the first 100–1,000 steps. Cause: Totally normal. The model is building basic representations. Don't panic, don't restart.

Color Shift in Samples

Symptom: Generated images have a gray or washed-out appearance. Cause: Normalization mismatch: data is in $[0, 1]$ but the model expects $[-1, 1]$, or your denormalization is wrong. Fix: Double-check the entire normalization pipeline: training data, sampling output, display code.

NaN Loss

Symptom: Loss becomes NaN and never recovers. Cause: Usually overflow in sinusoidal time embeddings or divide-by-zero in the noise schedule. Fix: Ensure everything is in float32. Check schedule values at the boundaries ($t = 0$ and $t = T$).

Slow Convergence

Symptom: Model still produces bad samples after many steps. Cause: Diffusion models are slow by nature. Benchmarks: ~5K steps for recognizable MNIST samples, 50K+ for CIFAR-10. If you're within that range, keep training.

6.9 Monitoring Training

How do you know training is working? Two methods: look at the images, and look at the loss curve.

Visual Inspection

This is the most important monitoring tool. Every 1,000–5,000 steps, generate a grid of samples using the EMA model and look at them. If you see recognizable images, training is working. If you see blurry blobs, keep training. If you see the same image repeated, you have a bug.

The Loss Curve

The diffusion loss curve is characteristically noisy and slowly decreasing. Don't expect a smooth exponential decay like you'd see in classification. Use a moving average (window of 100 steps) to see the trend. The loss is not perfectly correlated with sample quality; a model at loss 0.05 might generate better images than one at loss 0.04. Visual inspection is the ground truth.

FID — The Standard Metric

Frchet Inception Distance (FID) is the standard quantitative metric for generative quality. It compares the distribution of real images to generated images using features from a pretrained InceptionV3 network. Lower is better. DDPM on CIFAR-10 achieves FID $\approx 3.17$.

FID is too expensive to compute during training (it requires thousands of generated samples per evaluation). For this course, visual inspection plus the loss curve is sufficient.

6.10 Saving Checkpoints

This is the bridge between Lecture 6 and Lecture 7. We need to save our trained model so that the next lecture can load it for sampling, and Lectures 8–9 can use it for conditioning experiments.

What to Save

A complete checkpoint contains everything needed to either resume training or generate samples:

  • Model state dict — the current training weights (for resuming training)
  • EMA state dict — the smoothed weights (for high-quality sampling)
  • Optimizer state dict — momentum buffers, adaptive learning rates (for resuming training)
  • Schedule dict — all precomputed noise schedule tensors
  • Step number — where training left off
def save_checkpoint(model, ema, optimizer, schedule, step, path='diffusion_mnist.pt'): torch.save({ 'model': model.state_dict(), # for continued training 'ema': ema.shadow_state_dict(), # for sampling (Lecture 7) 'optimizer': optimizer.state_dict(), 'schedule': schedule, 'step': step, }, path)
Key Insight
Why save both model and EMA weights? The model weights are what the optimizer updates — you need them to resume training. The EMA weights are the smoothed copy — they produce better samples and are what Lecture 7 loads for generation. Two copies, two purposes.

6.11 Putting It All Together

Here's the complete training pipeline, combining everything from this lecture. This is the script that, given 20 minutes on a GPU (or an hour on CPU), produces a model that generates recognizable images.

# Setup model = UNet(image_channels=1, base_channels=64, ...).to(device) schedule = prepare_schedule(cosine_schedule(T=1000), device) optimizer = AdamW(model.parameters(), lr=2e-4) ema = EMA(model, decay=0.9999) # Training loop for step in range(num_steps): x_0, _ = next(dataloader) # (B, 1, 28, 28) in [-1, 1] x_0 = x_0.to(device) loss = train_step(model, x_0, optimizer, schedule, device) ema.update(model) if step % 1000 == 0: # Generate samples with EMA model for monitoring ema.apply_to(model) samples = ddpm_sample(model, shape=(16, 1, 28, 28), schedule, device) show_images(samples) ema.restore(model) print(f"Step {step}, Loss: {loss:.4f}") if step % 5000 == 0: save_checkpoint(model, ema, optimizer, schedule, step)
