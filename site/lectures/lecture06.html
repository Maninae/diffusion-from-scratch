6.1 Data Loading & Preprocessing

Normalize to [−1, 1], Not [0, 1]

The model we've described so far predicts noise $\epsilon \sim \mathcal{N}(0, I)$, which is mean-zero and symmetric around the origin. Images in $[0, 1]$ are strictly positive, so the model has to simultaneously learn the signal's offset and the noise pattern. Therefore, a common strategy is to normalize images to $[-1, 1]$, centering the data around zero to match the noise distribution's symmetry.

The transform pipeline is:

transform = Compose([ ToTensor(), # [0, 255] → [0, 1] Normalize([0.5], [0.5]), # [0, 1] → [-1, 1] ]) dataset = MNIST(root='./data', train=True, transform=transform) dataloader = DataLoader(dataset, batch_size=64, shuffle=True)

When you want to display images, you reverse it: $x_{\text{display}} = (x + 1) / 2$, mapping back to $[0, 1]$. Our denormalize() utility handles this.

Implicit augmentation from noise

In classification, data augmentation (random flips, crops, color jitter) is essential to prevent overfitting. Diffusion models get much of this for free. During training, each image is paired with a random timestep $t$, producing a different noisy version every time. A single image seen at $t = 10$, $t = 100$, and $t = 900$ looks like three entirely different training examples, ranging from nearly clean to nearly pure noise.

Over the course of training, each image appears at hundreds of distinct noise levels. This provides far more variation than geometric augmentation alone, and it comes at no extra cost since it is already part of the training algorithm.

Traditional augmentation techniques (horizontal flips, random crops) are still used in larger-scale diffusion training on datasets like ImageNet, where they provide additional diversity. But their relative importance is lower than in classification: the noise-level variation already covers a large portion of what augmentation is meant to achieve.

6.2 The Training Loop — Algorithm 1 in Code

Let's expand the six-line DDPM training algorithm into real, working code. Each line of the algorithm maps to a concrete operation with specific shapes and device requirements.

Algorithm 1 — DDPM Training (Ho et al., 2020)
  1. repeat
  2. $\mathbf{x}_0 \sim q(\mathbf{x}_0)$ — sample a batch of clean images
  3. $t \sim \text{Uniform}(\{1, \ldots, T\})$ — sample random timesteps
  4. $\boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$ — sample noise
  5. Take gradient step on $\nabla_\theta \left\| \boldsymbol{\epsilon} - \boldsymbol{\epsilon}_\theta\!\left(\sqrt{\bar{\alpha}_t}\, \mathbf{x}_0 + \sqrt{1-\bar{\alpha}_t}\, \boldsymbol{\epsilon},\; t\right) \right\|^2$
  6. until converged

The complete training step:

def train_step(model, x_0, optimizer, schedule, device): # 1. Sample random timesteps — one per image in the batch t = randint(0, T-1, size=batch_size).to(device) # 2. Sample noise noise = randn_like(x_0) # (B, 1, 28, 28) # 3. Create noisy images using closed-form q(x_t | x_0) sqrt_alpha_bar = schedule.sqrt_alphas_cumprod[t] # (B,) sqrt_one_minus = schedule.sqrt_one_minus_alphas_cumprod[t] # (B,) # Reshape for broadcasting: (B,) → (B, 1, 1, 1) x_t = sqrt_alpha_bar[:, None, None, None] * x_0 + sqrt_one_minus[:, None, None, None] * noise # (B, 1, 28, 28) # 4. Predict noise noise_pred = model(x_t, t) # (B, 1, 28, 28) # 5. Compute loss loss = mse_loss(noise_pred, noise) # 6. Update weights optimizer.zero_grad() loss.backward() clip_grad_norm(model.parameters(), max_norm=1.0) optimizer.step() return loss.item()

Recall from Lecture 3 that the full ELBO objective contains $T$ weighted KL divergence terms, one per timestep. Ho et al. showed that dropping the per-timestep weighting and using a flat MSE between predicted and actual noise works better in practice. That simplified objective is exactly what step 5 in the code above computes.

Definition
The training loss. The simplified DDPM objective is: $$L_{\text{simple}} = \mathbb{E}_{t, \mathbf{x}_0, \boldsymbol{\epsilon}}\left[ \left\| \boldsymbol{\epsilon} - \htmlData{tip=The neural network with learned weights θ, predicting what noise was added}{\boldsymbol{\epsilon}_\theta}\!\left(\htmlData{tip=The noisy image at timestep t — constructed from the clean image and sampled noise}{\sqrt{\bar{\alpha}_t}\, \mathbf{x}_0 + \sqrt{1-\bar{\alpha}_t}\, \boldsymbol{\epsilon}},\; t\right) \right\|^2 \right]$$ In words: sample a clean image, add noise at a random timestep, predict the noise, and minimize the squared error between the predicted and actual noise.

6.3 Timestep Sampling Strategies

In the training loop above, step 1 samples timestep $t$ uniformly from $1$ to $T$, so the model sees every noise level equally often. This works well in practice, but not all timesteps contribute equally to learning: intermediate noise levels tend to carry more signal than the extremes. That asymmetry opens the door to smarter sampling strategies.

Uniform Sampling

The default: t = torch.randint(0, T, (batch_size,)). Each image in the batch gets an independent random timestep. Simple, effective, and what DDPM uses.

Why Uniform Is Suboptimal

Not all timesteps are equally valuable for the model to learn from. Consider what the model sees at different noise levels:

  • Low $t$ (little noise): the image is nearly clean. Predicting the (small amount of) noise is easy; the model barely needs to do anything. Loss is small, gradients are uninformative.
  • High $t$ (lots of noise): the image is nearly pure Gaussian noise. The model can't see the underlying image at all, so it's essentially predicting random noise from random noise. Also relatively easy in terms of loss magnitude.
  • Mid $t$: the hardest range. The signal is partially visible but heavily corrupted. The model has to work hard to separate signal from noise. These timesteps produce the most informative gradients.

Sampling the timesteps uniformly will spend a large fraction of training time compute learning from uninformative timesteps at the extremes.

Importance Weighting (P2)

P2 weighting (Perception Prioritized, Choi et al. 2022) reweights the loss by $1/(1 + \text{SNR}(t))$, which upweights mid-noise timesteps where the gradients are most useful. This improves FID scores, especially on complex datasets like CIFAR-10 and ImageNet.

Practical advice: start with uniform sampling. It's simpler and works well in practice. Switch to importance weighting if you're training on harder datasets and want to squeeze out better FID.

6.4 Gradient Clipping

Diffusion training loss can spike, especially in the first few hundred steps when the model is still learning basic structure, or when an unlucky batch happens to contain all high-noise timesteps. Without protection, a single bad batch can produce enormous gradients that blow up the model weights.

The fix is gradient clipping:

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

This computes the total $L_2$ norm of all gradients across all parameters. If the norm exceeds 1.0, every gradient is rescaled proportionally so the total norm is exactly 1.0. The direction of the update is preserved; only the magnitude is capped.

Key Insight
Gradient clipping doesn't change the direction of the optimization step; it only prevents catastrophically large steps. Think of it as a speed limit: the optimizer can go anywhere, but it can't go there too fast. This is standard practice in essentially all modern diffusion training.
Gradient clipping rescales vectors that exceed max_norm, preserving direction

6.5 EMA — Exponential Moving Average

With gradient clipping keeping training stable, we can turn to a subtler question: which weights should we actually use for generation? Counterintuitively, the best weights for generating samples are not the current training weights. They're a smoothed average of all recent training weights.

Why EMA Helps

During training, model weights oscillate around the optimum, overshooting in one direction, then correcting. These oscillations are fine for computing gradients (the optimizer handles them), but they produce noisy, inconsistent samples. EMA averages out the oscillations, yielding a smoother set of weights that generates higher-quality images.

The update rule is:

$$\theta_{\text{ema}} = \lambda \cdot \theta_{\text{ema}} + (1 - \lambda) \cdot \theta$$

With $\lambda = 0.9999$ (the standard decay), the EMA model changes very slowly. Each training step nudges it by just 0.01% toward the current weights. This heavy smoothing is what makes EMA so effective.

training weights θ EMA weights θema optimum

Implementation

Definition
EMA (Exponential Moving Average). A shadow copy of model parameters, updated after each training step as $\theta_{\text{ema}} \leftarrow \htmlData{tip=Keep 99.99 percent of the old shadow weights and blend in 0.01 percent of the current training weights}{0.9999 \cdot \theta_{\text{ema}} + 0.0001 \cdot \theta}$. Use EMA weights for sampling and evaluation. Use regular weights for gradient computation and optimizer updates. Never compute gradients through the EMA model.

6.6 Learning Rate Schedule

Learning rate scheduling affects training stability and convergence speed in any deep learning model, and diffusion models are no exception. The most common strategy combines a gradual warmup phase with a long decay.

Linear Warmup

During an initial warmup period, the learning rate increases linearly from 0 to the target value (e.g., $2 \times 10^{-4}$). Early in training the model's predictions are essentially random, so large learning rates cause wild parameter swings. Warmup lets the model establish basic structure before the optimizer starts making aggressive updates.

Cosine Decay

After warmup, the learning rate follows a cosine curve from the target value down to 0. This schedule is gentle: it holds near the peak for a long time, then gradually decreases as training matures. It's the default in most modern training pipelines.

The Practical Recipe

For small, simple datasets, the simplest approach works fine: Adam with a constant learning rate of $2 \times 10^{-4}$. This is what the original DDPM paper used, and for grayscale digits it's all you need.

For more complex datasets (CIFAR-10, ImageNet), the full recipe is: AdamW with $\text{lr} = 2 \times 10^{-4}$, linear warmup for 1,000 steps, cosine decay to 0. AdamW adds decoupled weight decay regularization, which is modern best practice.

6.7 Monitoring Training

How do you know training is working? Two methods: look at the images, and look at the loss curve.

Visual Inspection

This is the most important monitoring tool. Every 1,000–5,000 steps, generate a grid of samples using the EMA model and look at them. If you see recognizable images, training is working. If you see blurry blobs, keep training. If you see the same image repeated, you have a bug.

Visual inspection carries more weight in generative modeling than in discriminative tasks like classification, where accuracy on a held-out set gives a clear signal. The qualities that matter for generated images, such as realism, diversity, and coherence, are inherently subjective and difficult to capture in a single number. Automated metrics like FID measure part of the picture, but what counts as "good" depends on the specific use case, which is why looking at samples remains central to diffusion model development.

The Loss Curve

The diffusion loss curve is characteristically noisy and slowly decreasing. Don't expect a smooth exponential decay like you'd see in classification. Use a moving average (window of 100 steps) to see the trend. The loss is not perfectly correlated with sample quality; a model at loss 0.05 might generate better images than one at loss 0.04. Visual inspection remains the most reliable indicator.

In practice, the $L_2$ pixel-space loss on a diverse dataset tends to stay jagged and spiky throughout training, never reaching the clean convergence pattern familiar from classification or regression. Yet periodic sample grids will show realism and coherence improving steadily behind that noise. This disconnect between loss value and output quality is one of the more counterintuitive aspects of diffusion training, and it reinforces why visual inspection carries so much weight.

FID — The Standard Metric

Frchet Inception Distance (FID) is the standard quantitative metric for generative quality. It compares the distribution of real images to generated images using features from a pretrained InceptionV3 network. Lower is better. DDPM on CIFAR-10 achieves FID $\approx 3.17$.

FID is too expensive to compute during training (it requires thousands of generated samples per evaluation). For this course, visual inspection plus the loss curve is sufficient.

6.8 Saving Checkpoints

This is the bridge between Lecture 6 and Lecture 7. We need to save our trained model so that the next lecture can load it for sampling, and Lectures 8–9 can use it for conditioning experiments.

What to Save

A complete checkpoint contains everything needed to either resume training or generate samples:

  • Model state dict — the current training weights (for resuming training)
  • EMA state dict — the smoothed weights (for high-quality sampling)
  • Optimizer state dict — momentum buffers, adaptive learning rates (for resuming training)
  • Schedule dict — all precomputed noise schedule tensors
  • Step number — where training left off
def save_checkpoint(model, ema, optimizer, schedule, step, path='diffusion_mnist.pt'): torch.save({ 'model': model.state_dict(), # for continued training 'ema': ema.shadow_state_dict(), # for sampling (Lecture 7) 'optimizer': optimizer.state_dict(), 'schedule': schedule, 'step': step, }, path)
Key Insight
Why save both model and EMA weights? The model weights are what the optimizer updates; you need them to resume training. The EMA weights are the smoothed copy; they produce better samples and are what Lecture 7 loads for generation. Two copies, two purposes.

6.9 Putting It All Together

Here's the complete training pipeline, combining everything from this lecture. This is the script that, given 20 minutes on a GPU (or an hour on CPU), produces a model that generates recognizable images.

# Setup model = UNet(image_channels=1, base_channels=64, ...).to(device) schedule = prepare_schedule(cosine_schedule(T=1000), device) optimizer = AdamW(model.parameters(), lr=2e-4) ema = EMA(model, decay=0.9999) # Training loop for step in range(num_steps): x_0, _ = next(dataloader) # (B, 1, 28, 28) in [-1, 1] x_0 = x_0.to(device) loss = train_step(model, x_0, optimizer, schedule, device) ema.update(model) if step % 1000 == 0: # Generate samples with EMA model for monitoring ema.apply_to(model) samples = ddpm_sample(model, shape=(16, 1, 28, 28), schedule, device) show_images(samples) ema.restore(model) print(f"Step {step}, Loss: {loss:.4f}") if step % 5000 == 0: save_checkpoint(model, ema, optimizer, schedule, step)
