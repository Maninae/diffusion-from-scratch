The Forward Process & Noise Schedules

How to destroy an image in exactly the right way, and why the math that lets us skip ahead to any noise level is the key to efficient training.

Forward Process Noise Schedules SNR
← Why Diffusion? The Reverse Process & the Simplified Loss →

Diffusion starts with destruction. We'll define the forward noising process step-by-step, then discover the key mathematical shortcut, cumulative products $\bar{\alpha}_t$, that lets us jump to any noise level in a single operation. Along the way, we'll build intuition for noise schedules, signal-to-noise ratios, and why these choices quietly shape everything the model learns.

This Lecture Is For You If
  • You want to understand how clean images become noise, and what controls that process
  • You're comfortable with Gaussians and basic probability

2.1 The Forward Markov Chain

In Lecture 1, we said diffusion models learn to reverse a destruction process. Now let's define that process precisely.

Starting from a clean image $x_0$, the forward process adds a small amount of Gaussian noise at each step, producing a sequence $x_0, x_1, x_2, \ldots, x_T$. Each step is defined by:

$$q(x_t \mid x_{t-1}) = \mathcal{N}\!\left(x_t;\; \sqrt{1 - \beta_t}\, x_{t-1},\; \beta_t\, I\right)$$

At step $t$, we do two things to the previous image $x_{t-1}$:

  • Shrink the signal by multiplying by $\sqrt{1 - \beta_t}$. This slightly reduces the magnitude of the image.
  • Add noise sampled from $\mathcal{N}(0, \beta_t\, I)$. This injects a small amount of random static.

The parameter $\beta_t$ is the noise variance at step $t$. It's small, typically ranging from $\beta_1 = 0.0001$ to $\beta_T = 0.02$.

The shrinking factor $\sqrt{1 - \beta_t}$ is crucial: without it, the variance of $x_t$ would grow without bound as we keep adding noise. The shrinking ensures the overall variance stays controlled.

This is a Markov chain: each step depends only on the previous state. And it's completely fixed: there are no learnable parameters in the forward process. The neural network only appears in the reverse process.

def single_forward_step(x_prev, beta_t):
    # One step of the forward noising chain
    noise = sample_gaussian(shape=x_prev.shape)
    x_t = sqrt(1 - beta_t) * x_prev + sqrt(beta_t) * noise
    return x_t

After $T = 1000$ steps, the cumulative effect is devastating: the original image is completely gone. $x_T$ is indistinguishable from pure Gaussian noise $\mathcal{N}(0, I)$. Every trace of the face, the digit, the landscape: erased. That's exactly what we want.

2.2 The Cumulative Products — αt and ᾱt

Working with individual $\beta_t$ values gets tedious quickly. Let's introduce two quantities that make everything cleaner.

Definition

Signal retention: $\alpha_t = 1 - \beta_t$. This is the fraction of signal that survives step $t$.

Cumulative signal retention: $\bar{\alpha}_t = \prod_{s=1}^{t} \alpha_s$. This is the total fraction of the original signal that survives from step $0$ to step $t$.

Think of $\bar{\alpha}_t$ as a measure of how much of the original image is left at step $t$:

  • At $t = 0$: $\bar{\alpha}_0 \approx 1$ — nearly all signal, almost no noise
  • At $t = T$: $\bar{\alpha}_T \approx 0$ — no signal, pure noise

These cumulative products are precomputed once when you set up the model and stored as tensors. They're the heart of the noise schedule.

betas = linear_schedule(T=1000)          # (T,)
alphas = 1 - betas                     # (T,)
alphas_cumprod = cumulative_product(alphas) # (T,) — this is ᾱ_t

2.3 The Closed-Form Shortcut

Training a diffusion model means generating millions of $(x_0, t, \varepsilon)$ triples. If we had to iterate the forward chain step-by-step to get $x_t$ from $x_0$, this would be impossibly slow: 500 sequential noise operations just to produce a single noised image for one gradient step.

Fortunately, because each step adds Gaussian noise, and Gaussians compose beautifully, we can derive a closed-form expression that jumps directly from $x_0$ to any noised $x_t$:

$$q(x_t \mid x_0) = \mathcal{N}\!\left(x_t;\; \sqrt{\bar{\alpha}_t}\, x_0,\; (1 - \bar{\alpha}_t)\, I\right)$$

In sampling form, this becomes the single most important equation in diffusion:

Key Equation
$$x_t = \sqrt{\bar{\alpha}_t}\, x_0 + \sqrt{1 - \bar{\alpha}_t}\, \varepsilon, \quad \varepsilon \sim \mathcal{N}(0, I)$$

This is a weighted sum of two components:

  • $\sqrt{\bar{\alpha}_t} \cdot x_0$ — the signal component. How much of the original image survives.
  • $\sqrt{1 - \bar{\alpha}_t} \cdot \varepsilon$ — the noise component. How much random noise has been injected.

The two coefficients are complementary: $(\sqrt{\bar{\alpha}_t})^2 + (\sqrt{1-\bar{\alpha}_t})^2 = 1$. As $t$ increases, the signal fades and the noise grows, a smooth interpolation from data to noise.

Concrete Example

Say we want to generate the noised version of an image at timestep $t = 250$ out of $T = 1000$. The cumulative schedule tells us how much signal remains at that point: $\bar{\alpha}_{250} = 0.5$, meaning half the original signal has been preserved and half has been replaced by noise. Plugging into the closed-form equation:

$x_{250} = \sqrt{0.5} \cdot x_0 + \sqrt{0.5} \cdot \varepsilon \approx 0.707 \cdot x_0 + 0.707 \cdot \varepsilon$

The signal and noise coefficients are equal, so the image and noise contribute in exactly the same proportion. Visually, you'd see a ghostly outline of the original with heavy static overlay.

def q_sample(x_0, t, alphas_cumprod):
    """Noise x_0 to timestep t in one shot."""
    noise = sample_gaussian(shape=x_0.shape)      # ε ~ N(0, I)
    sqrt_alpha_bar = sqrt(alphas_cumprod[t])     # signal coefficient
    sqrt_one_minus = sqrt(1 - alphas_cumprod[t]) # noise coefficient
    x_t = sqrt_alpha_bar * x_0 + sqrt_one_minus * noise
    return x_t, noise  # return noise too — it's the training target!

One multiplication, one addition, constant time regardless of $t$. This is why diffusion training is efficient despite the 1000-step forward chain.

Looking Ahead

Notice that the closed-form writes $x_t$ as a deterministic function of $x_0$ and a separate noise sample $\varepsilon$. Keeping the randomness external to the computation, rather than baked into a single sampling operation, is called the reparameterization trick, the same idea that makes VAEs trainable. It will turn out to be critical for diffusion training too: this separation is what allows gradients to flow through $x_t$ during backpropagation. We'll see exactly how in Lecture 3.

2.4 Noise Schedules

Recall that at every timestep, we add a bit more noise to the image. The value $\beta_t$ controls exactly how much noise gets added at step $t$. It's the knob that governs the pace of destruction.

This is entirely a design choice. You could blast the image with massive noise from step one and destroy it almost immediately. You could add a tiny, uniform amount at every step and let the process creep along. There are infinitely many ways to configure how $\beta_t$ ramps from start to finish.

But the choice has real consequences for training. The shape of the $\beta_t$ curve determines which noise levels the model spends most of its time learning to handle. Rush through the early steps too fast, and the model rarely sees medium-noise images, the ones where learning is hardest and most productive. Go too slow, and you waste training compute on nearly-clean images the model can already handle.

Three schedules have emerged as practical defaults:

Linear Schedule (DDPM)

The original DDPM (Ho et al., 2020) used a linear schedule: $\beta_t$ increases linearly from $\beta_1 = 0.0001$ to $\beta_T = 0.02$.

Simple and effective, but it has a problem. The $\bar{\alpha}_t$ curve drops quickly in the early steps and then flattens. This means the model spends too many timesteps in the "nearly destroyed" regime and not enough in the perceptually important middle range.

Cosine Schedule (Improved DDPM)

Nichol & Dhariwal (2021) proposed a cosine schedule that defines $\bar{\alpha}_t$ directly:

$$\bar{\alpha}_t = \cos^2\!\left(\frac{t/T + s}{1 + s} \cdot \frac{\pi}{2}\right), \quad s = 0.008$$

The cosine curve gives a much smoother SNR decay. Information is preserved longer in the early steps, and the model spends more time at medium noise levels, exactly where the denoising problem is most interesting. The small offset $s$ prevents $\bar{\alpha}_T$ from hitting exactly zero.

Sigmoid Schedule

The sigmoid schedule maps timesteps through a sigmoid function to interpolate between $\beta_{\text{start}}$ and $\beta_{\text{end}}$:

$$\beta_t = \sigma\!\left(\frac{t}{T} \cdot 12 - 6\right) \cdot (\beta_{\text{end}} - \beta_{\text{start}}) + \beta_{\text{start}}$$

where $\sigma$ is the standard sigmoid. The S-shaped ramp changes $\beta_t$ slowly at both extremes and quickly in the middle, producing an $\bar{\alpha}_t$ curve that sits between linear and cosine: smoother than linear, less conservative than cosine. It has become a popular default in recent implementations for its robustness across datasets and resolutions.

def linear_schedule(T, beta_start=0.0001, beta_end=0.02):
    return linspace(beta_start, beta_end, T)

def cosine_schedule(T, s=0.008):
    steps = linspace(0, T, T+1)
    f_t = cos((steps/T + s) / (1+s) * pi/2) ** 2
    alphas_cumprod = f_t / f_t[0]
    betas = 1 - alphas_cumprod[1:] / alphas_cumprod[:-1]
    return clip(betas, max=0.999)

The three schedules start and end at the same place (pure signal and pure noise) but they differ dramatically in how they distribute the transition. The linear schedule burns through signal quickly in the early steps, wasting capacity on timesteps where the image is already mostly destroyed. The cosine schedule preserves signal longer, giving the model more training time at medium noise levels, exactly where the denoising problem is hardest and learning is richest.

2.5 Signal-to-Noise Ratio

We've now seen three schedules that distribute the transition from image to noise in very different ways, but how do we compare them on equal footing? We need a single quantity that captures how much signal remains relative to noise at any given timestep. That quantity is the signal-to-noise ratio (SNR).

$$\text{SNR}(t) = \frac{\bar{\alpha}_t}{1 - \bar{\alpha}_t}$$

This is the ratio of signal power to noise power at timestep $t$:

  • At $t = 0$: SNR is very large (mostly signal)
  • At $t = T$: SNR $\approx 0$ (pure noise)
  • The hardest timesteps are in the middle range, where signal and noise are roughly balanced, where the model can see some structure but must fill in significant detail

In practice, the log-SNR metric is more useful because it spreads the range linearly:

$$\log\text{SNR}(t) = \log \bar{\alpha}_t - \log(1 - \bar{\alpha}_t)$$

Log-SNR gives us a unified lens for comparing different noise schedules. A "good" schedule should decrease the log-SNR smoothly and spend enough timesteps in the difficult mid-range.

2.6 Visualizing the Forward Process

To build intuition, let's watch what happens to a single image as the forward process runs.

At $t = 0$, you see the original image clearly. By $t = 100$, there's a subtle graininess, like a slightly noisy photograph. At $t = 250$, you can still make out the overall shape and structure, but details are fading. At $t = 500$, it's a ghostly outline buried in static.

By $t = 750$, you're squinting to see any structure at all. At $t = 1000$, it's pure noise. No trace of the original image remains.

Now think about this from the model's perspective. At each timestep, the model sees $x_t$ and must predict the noise $\varepsilon$ that was added. At low $t$ (clean images), this is easy; the noise is small and the image provides strong context. At high $t$ (nearly pure noise), the model must essentially hallucinate plausible image structure.

The choice of noise schedule determines how often the model trains at each difficulty level.

Key Insight

The signal decomposition $x_t = \sqrt{\bar{\alpha}_t}\, x_0 + \sqrt{1 - \bar{\alpha}_t}\, \varepsilon$ shows that every noisy image is a weighted blend of signal and noise. You can visualize the two components separately: the fading ghost of the original (signal) and the growing static (noise). Their sum is what the model actually sees at each step.

PyTorch Reference

Here's how the forward process looks in real PyTorch code. We'll build this from scratch in the notebooks; this is just a reference to ground the pseudocode in practice.

PyTorch
import torch
import torch.nn.functional as F

def linear_schedule(T, beta_start=1e-4, beta_end=0.02):
    """Linear noise schedule from DDPM."""
    return torch.linspace(beta_start, beta_end, T)

def cosine_schedule(T, s=0.008):
    """Cosine noise schedule from Improved DDPM."""
    steps = torch.linspace(0, T, T + 1)
    f_t = torch.cos((steps / T + s) / (1 + s) * torch.pi / 2) ** 2
    alphas_cumprod = f_t / f_t[0]
    betas = 1 - alphas_cumprod[1:] / alphas_cumprod[:-1]
    return torch.clamp(betas, max=0.999)

def q_sample(x_0, t, sqrt_alphas_cumprod, sqrt_one_minus_alphas_cumprod, noise=None):
    """Forward diffusion: noise x_0 to timestep t."""
    if noise is None:
        noise = torch.randn_like(x_0)              # ε ~ N(0, I)
    sqrt_ab = sqrt_alphas_cumprod[t]             # (B,) → (B, 1, 1, 1)
    sqrt_om = sqrt_one_minus_alphas_cumprod[t]   # (B,) → (B, 1, 1, 1)
    while sqrt_ab.dim() < x_0.dim():
        sqrt_ab = sqrt_ab.unsqueeze(-1)
        sqrt_om = sqrt_om.unsqueeze(-1)
    return sqrt_ab * x_0 + sqrt_om * noise, noise

2.7 Looking Ahead

The forward process is fully specified: pick a schedule, precompute the cumulative products, and any timestep is one tensor multiplication away. Destruction is trivially easy. Reversal is the hard part.

The next lecture turns the chain around and asks what it would take to go from noise back to data. The true reverse distribution is intractable, so the derivation takes a detour through the ELBO, introduces a clever reparameterization that swaps predicting the clean image for predicting the noise, and arrives at a loss function so simple it's almost suspicious: mean squared error between two noise tensors. That simplified loss is the training objective that makes diffusion practical.
